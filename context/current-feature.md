# Current Feature

Custom Types Phase 2: Use Custom Types

## Status

In Progress

## Goals

- A custom type's items hold text like a Note (title, description, Markdown content, tags, optional collection), stored as TEXT; `createItem` and `updateItem` accept a custom type by id, owned by the signed-in user, otherwise "Type not found"; the free item limit still applies
- The New Item dialog lists custom types after the built-in ones and shows the Note fields for one; the edit form keeps the type locked
- Item cards, dashboard rows, the drawer header, the edit form and search results show the custom type's own icon, colour and name; quick search and `/search` match a type by name
- Counts agree between the sidebar and `/types`, and lists and counts are revalidated after item mutations
- Export (JSON and ZIP) includes the user's custom types and uses their names on items
- The Pro plan lists "Custom item types" on the pricing section and the plan card
- Browser checks (create, edit, open and search items of a custom type, export, mobile) and `npm run build`

## Notes

- Spec: @context/features/custom-types-phase-2-spec.md (depends on phase 1, already merged)
- Tests: `createItem` and `updateItem` with a custom type (own type accepted, other user's or unknown id rejected, free limit kept), type queries order and counts, card/row/header show the custom icon and colour, New Item dialog lists custom types, export lists them, the Pro plan lists custom types
- Custom types are text only; per-type fields and file or link custom types are out of scope
- The landing page demo for custom types is a separate follow-up
